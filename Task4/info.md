В ходе анализа планируемой миграции были выявлены следующие проблемы:

![Диаграмма Исикавы](/Task4/diagramm.png)

1. Персонал
    - Критически малое число IT-специалистов. <br>Для перехода к целевому решению требуется значительно больше IT-специалистов. <br>Для решения возможно расширить штат или отдать часть задач на аутстафф/аутсорс.
    - Отсутствие у IT-отдела компетенций в предложенных технологиях. <br>В целевом решении используется значительное число новых для компании технологий (разрабатываемые решения, data governance платформа, новая система для анализа данных). <br>Возможное решение: расширение штата, повышение квалификации или аутстафф/аутсорс.
2. Инфраструктура
    - Критически малое число серверов для перехода к целевому решению. <br>Мощностей 1 сервера будет недостаточно для перехода к целевому решению, помимо этого, отсутствует какое-либо резервирование. <br>Решением может быть закупка новых серверов или аренда облачной инфраструктуры.
    - Отсутствует развитая сетевая инфраструктура. <br>В целевом решении значительно возрастает число сетевых взаимодействий, для чего имеющаяся инфраструктура не была расчитана. <br>Решением может быть закупка новых серверов или аренда облачной инфраструктуры.
3. Процессы
    - Отсутствие процессов разработки ПО как таковых. <br>В целевом решении предполагается разрботка новых программных систем, имеющих свой жизненный цикл и требующих наличия компетенций от IT-департамента. <br>Для решения возможно расширить штат или провести соответствущее обучение.
    - Возможное несоответствие правил разграничения доступа бизнес-процессам. <br>При внедрении разграничения доступа может возникнуть ситуация, когда для выполнения своих обязанностей сотруднику необходим доступ к ресурсу, упущенному из виду при подготовке решения. <br>Для избежания подобной ситуации предлагается постепенный переход и возможность оперативно дать необходимый доступ к данным.
4. Программное обеспечение
    - Сложности с поставками и поддержкой ПО для предложенных технологий. <br>Поставщики ПО могут отказаться от своих обязательств, могут возникнуть трудности с оплатой услуг поставщиков, а решения с открытым исходным кодом вообще не имеют поддержки. <br>Во избежании подобных проблем необходим тщательный анализ планируемых к использованию технологий с учетом таких аспектов.
    - Высокий риск миграции 1С из файлового в клиент-серверный режим с разграничением прав доступа. <br>Миграция данных подвержена значительным рискам, особенно с учетом специфики платформы 1С. <br>Решение: резервное копирование мигрируемых данных и привлечение специалистов с высокой компетенцией в 1С.
5. Интеграция
    - Риски контрагента после реализации API для лаборатории. <br>Лаборатория отмечена как внешняя система, степень вляния на которую не ясна в полной мере. Управление лабораторией может отказаться от интеграции с API. <br>Решение - заключение договора, в которм будут описан протокол взаимодействия и сроки интеграции.
    - Использование специфичных механизмов интеграции для 1C. <br>При переходе на "тонкий" клиент 1С OLE-интеграция может оказзаться невозможной. <br>Решение - привлечение специалистов с высокой компетенцией в 1С и интеграция с помощью актуальных технологий с сервером
